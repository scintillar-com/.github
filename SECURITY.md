# Reporting security issues

We take security bugs in Scintillar tools seriously, and we appreciate you disclosing them responsibly. We'll credit you for your findings unless you'd rather stay anonymous.

Scintillar tools are maintained by a community on a best-effort basis. They're meant for hobbyists and small projects, not business-critical operations, and come with no security SLA. We still fix what we're told about as quickly as we reasonably can.

## How to report

**Please don't open a public issue.** Instead, use the **Report a vulnerability** button in the affected repository's **Security** tab:

`https://github.com/scintillar-com/<repository>/security/advisories/new`

Include what you found, which version and deployment it affects, and steps to reproduce it if you can.

If private reporting isn't available for that repository, email **security@scintillar.com**.

## What happens next

1. We acknowledge your report, usually within a week.
2. We confirm the issue, work on a fix, and may ask you for more details along the way.
3. We publish a fixed release and a security advisory, crediting you if you'd like.

If you haven't heard back within two weeks, follow up at **security@scintillar.com**.

## Supported versions

Fixes go into the latest release of each tool. Since you host your own instance, keep it up to date to receive them.

## Third-party dependencies

Report vulnerabilities in third-party packages to their maintainers. For npm packages, you can also use the [npm security contact form](https://www.npmjs.com/support).
